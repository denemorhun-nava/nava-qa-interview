Goal

Your goal is to design a test strategy for the Login Flow.

  • Align on Acceptance Criteria
  • Write and execute test cases
  • Find and log bug(s)

Context

  • Users must log in before accessing the dashboard or continuing their workflow.
  • Login is handled through a mocked backend API and user data store.
  • The login page has frontend field validations for username and password.
  • After Sign-in, the mocked backend determines whether the user has access.
  • Users may have different account states: active, locked, or disabled.
  • Users may have different roles: admin or standard user.

⚑ Clarify scope, authentication behavior, UI validations and any missing requirements before testing.

Username Field

  • Required field
  • Greater than 5 characters, less than 21 in length
  • Does not allow spaces
  • Only alphanumeric characters and . are allowed — a single @ is also permitted (e.g. abc.123@navapbc.com)
  • Case insensitive

Password Field

  • Required field
  • Must always be masked
  • Supports alphanumeric characters
  • Greater than 5 characters, less than 11 in length
  • secret! combined with any valid username is the mock password to access the dashboard

Page-level Validations

  • Performed when Sign in is clicked
  • Validation messages appear under the field they apply to
  • Messages: "This field is required" · "Invalid username/password"

Dashboard

  • User should be greeted with the username used to log in
  • This exercise only covers the Standard user view
  • Clicking Sign out should end the session

Database Schema

TABLE Users (
    user_id              INT PRIMARY KEY AUTO_INCREMENT,
    username             VARCHAR(17) UNIQUE NOT NULL,
    email                VARCHAR(100) UNIQUE NOT NULL,
    password_hash        VARCHAR(255) NOT NULL,
    account_status       VARCHAR(20) NOT NULL,
    role                 VARCHAR(20) NOT NULL,
    failed_login_attempts INT DEFAULT 0,
    last_login_at        DATETIME NULL,
    locked_at            DATETIME NULL,
    registration_date    DATETIME DEFAULT CURRENT_TIMESTAMP
)
